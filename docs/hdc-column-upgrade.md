# HDC column upgrade — 1, 2, 3 และ 5 ปี

## ขอบเขตและสัญญาข้อมูล

`getEpiSchemas()` เป็น schema ฝั่ง GAS; `hdcSourceFields()` เป็น allowlist ฝั่งนำเข้า มี contract test เทียบให้ตรงกันทุกอายุ เก็บ `addr`, `check_typearea`, `nation`, `discharge`, `g_hbv`, `g_dtp`, `g_hib`, `g_opv`, `g_mmr`, `g_rv`, `g_pcv` และคู่ `*_hospcode` / `*_input_hosp` สำหรับทุกคอลัมน์วัคซีนเดิม

- `check_typearea` คือชื่อจริง ยอมรับ `heck_typearea` เป็น alias เฉพาะตอนอ่านไฟล์
- `hoscode` หมายถึงหน่วยรับผิดชอบบุคคล ไม่ถูกแทนที่ด้วยหน่วยที่ฉีดหรือหน่วยบันทึก
- รหัสหน่วยฉีด/หน่วยบันทึกเก็บเป็นข้อความ 5 ตำแหน่ง รองรับอักษรและตัวเลขตามไฟล์ตัวอย่าง เช่นรหัสรูปแบบ `AE123`; รหัสตัวเลขที่ Excel ทำศูนย์นำหน้าหายเติมให้ครบ 5 หลัก
- CID ในไฟล์ตัวอย่างทั้ง 4 ชุดถูกปิดบังด้วย `*` และมีค่าซ้ำ ห้ามใช้ CID ที่ปิดบังจับคู่บุคคล
- Upsert ใช้ `(fiscal_year, hoscode, pid)`; ถ้าไม่มี PID ต้องมี CID ตัวเลขครบ 13 หลัก หาก PID เปลี่ยน ใช้ CID ไม่ปิดบังจับคู่ได้เฉพาะเมื่อพบแถวเดียวในปีและหน่วยบริการนั้น
- ไม่จับคู่ด้วยเพศ วันเกิด หรือรหัสบ้านซึ่งแก้ไขได้; หากชีตเดิมมี identity ซ้ำ ระบบหยุดให้ตรวจข้อมูลก่อน ไม่รวมคนโดยเดา
- แถวเก่าไม่มีปีงบประมาณไม่ถูกนำไปแสดงปนกับปีที่เลือกหรือ deactivate; ต้องระบุปีจริงหลังตรวจสอบต้นทาง

`source_columns` เป็น JSON array รายแถวของคอลัมน์ที่มีหลักฐานว่าเคยนำเข้ามา รักษาประวัติรายการคอลัมน์เมื่อไฟล์เก่าขาดฟิลด์ใหม่ และเพิ่มชื่อคอลัมน์จากค่าที่ไม่ว่างของข้อมูลเก่า ค่าว่างในชีตเก่าที่ไม่มี manifest ยังยืนยันไม่ได้ว่าไฟล์มีคอลัมน์นั้นจริง

## Upload / Update

อ่าน Excel (`xlsx`, `xls`) และ JSON array ใช้ parser เดียวกันใน preview และก่อนบันทึก ตรวจทุกแถวก่อนเริ่มส่ง รวมวันที่จริง คอลัมน์ที่ไม่รองรับ หัวซ้ำ รหัสบุคคลซ้ำ และชื่อไฟล์ EPI ที่ไม่ตรงกลุ่มอายุ หากพบฟิลด์ใหม่ที่ยังไม่รองรับจะหยุดพร้อมรายชื่อฟิลด์ ไม่ทิ้งเงียบ

- **เติม / อัปเดต (ค่าเริ่มต้น):** คอลัมน์ไม่ได้ส่งมาคงค่าเดิม เซลล์ว่าง/null ที่ส่งมาล้างค่านั้น ไม่ deactivate บุคคลที่หายจากไฟล์
- **ซิงค์ไฟล์เต็ม:** ใช้ไฟล์ครบทุกคนของหน่วยบริการที่มีอยู่ในไฟล์ หลังได้รับครบทุก chunk จึง deactivate รายชื่อที่ไม่อยู่ใน batch เฉพาะปีและหน่วยบริการที่ server ตรวจพบเอง หน่วยบริการที่ไม่มีสักแถวในไฟล์จะไม่ถูกล้าง
- เก็บ receipt ใน `epi_import_batches`: `batch_id`, `target_table`, `fiscal_year`, `mode`, `total_chunks`, `completed_chunks`, `hoscodes`, `status`, `updated_at`
- `completed_chunks` เก็บ index และ SHA-256 fingerprint ของ payload; chunk ซ้ำเดิมไม่เขียนซ้ำ แต่ payload ต่างกันใน index เดิมถูกปฏิเสธ
- ใช้ ScriptLock ครอบการเขียน ป้องกัน batch เก่าที่ขอบเขตทับ batch ใหม่กลับมาเขียนหรือ cleanup
- การนำเข้าเป็นการเขียนทีละ chunk ไม่ใช่ transaction ทั้งไฟล์: ถ้าล้มเหลว แถวจาก chunk ที่สำเร็จอาจแสดงแล้ว แต่ batch ที่ไม่ครบ cleanup ไม่ได้ ให้นำเข้าไฟล์ครบใหม่ แล้วประมวลผล summary อีกครั้ง
- Metadata ระบบและ AI ไม่รับจากไฟล์นำเข้า; ค่า AI เดิมรักษาไว้ ไม่ถือว่าเป็นผลวิเคราะห์ใหม่หลังข้อมูลเปลี่ยน

## มุมมองที่ 1

`AGE_VACCINES` กำหนดชื่อและลำดับกลาง ใช้ร่วมกันในหน้ารายบุคคล ประวัติ และ Excel พร้อมวัคซีนตามอายุ การคำนวณ summary ใช้ `evaluateAgeView1()` เช่นเดียวกับหน้ารายบุคคล กฎรายปีและ date_checks เดิมถูกอ่านมาประกอบโดยไม่ reset ชีต `vaccine_rules`

| อายุ | รายการ |
| --- | --- |
| 1 ปี | BCG แรกเกิด; HBV แรกเกิด; DTP 2/4/6 เดือน; HBV 2/4/6 เดือน; Hib 2/4/6 เดือน; IPV 2/4 เดือน; OPV 6 เดือน; MMR 9 เดือน; Rota 2 เดือนและครบชุด; PCV 2/4/6 เดือน (แสดงนอกแผน ไม่นับความครบถ้วน) |
| 2 ปี | PCV 1 ปี; LAJE/JE 1 ปี; DTP/OPV 1 ปี 6 เดือน; MMR1 เก็บตก; MMR2 1 ปี 6 เดือน |
| 3 ปี | LAJE2/JE3 |
| 5 ปี | DTP/OPV 4 ปี |

รายการที่ไม่มีกฎ active ตรงกับฟิลด์ต้นทาง ไม่ยืนยัน mapping หรือไม่มีข้อมูลคอลัมน์เพียงพอ แสดง **ข้อมูลไม่พอประเมิน** แยกจากยังไม่ถึงอายุและไม่พบวันที่ ไม่คิดเป็นขาดวัคซีนและไม่นับในตัวหาร summary จำนวนรายการที่ไม่พอประเมินแสดงแยกใน Dashboard

รายการมีทางเลือก: หากมีวันที่ครบทางเลือกที่ยืนยันได้แล้ว สามารถประเมินทางเลือกนั้นได้แม้ไฟล์ไม่มีอีกทางเลือก เช่นมี LAJE2 แล้วแต่ไม่มีคอลัมน์ JE3 หากไม่มีวันที่ LAJE2 และไม่มีคอลัมน์ JE3 ยังสรุปว่าขาดไม่ได้

### Mapping ที่ยังต้องยืนยันจากเจ้าของข้อมูล

- OPV 6 เดือน: เอกสารเดิมมีทั้ง `opv1_date` และ `opv3_date`; แสดงทั้งสองฟิลด์เป็นหลักฐานใต้รายการ OPV 6 เดือน แต่ไม่เลือกแทนกัน
- HBV 4/6 เดือน: แสดง `hbv3_date` / `hbv4_date` ตาม mapping เดิม พร้อมสถานะรอยืนยันก่อนคำนวณผลรายชนิด
- PCV 1 ปี: ไฟล์ 2 ปีไม่มี `pcv4_date`; ไม่เดาว่า `pcv1`–`pcv3` เป็นเข็ม 1 ปี
- JE3: ไฟล์ 3/5 ปีไม่มี `je3_date`; schema รองรับแล้ว แต่ค่าไม่มีคอลัมน์ยังไม่เท่ากับเซลล์ว่าง

การยืนยันครั้งต่อไปต้องปรับรายการกลางและ contract tests พร้อมกฎรายปีที่เกี่ยวข้อง ไม่ใช้ `seedVaccineRules(..., true)` เพราะจะ reset กฎทั้งปี

## มุมมองที่ 2 และ export

ผลรายบุคคลคง `result` จาก HDC และประวัติแสดงทุกเข็มที่โหลดมา รวมหน่วยฉีด/หน่วยบันทึก เพิ่มที่อยู่ ประเภทพื้นที่และรหัสหมู่บ้าน Excel เก็บคอลัมน์วัคซีนและกลุ่ม HDC ครบ ส่วน PDF เป็นรายชื่อพร้อมที่อยู่/ประเภทพื้นที่และผล ไม่ใช่ประวัติครบทุกเข็ม

มุมมองที่ 1 export เฉพาะวัคซีนในกลุ่มอายุ; มุมมองที่ 2 export ทุกคอลัมน์วัคซีนที่โหลดมา การกรองประเภทพื้นที่ไม่ได้เปลี่ยนประชากรเป้าหมายโดยอัตโนมัติ

Summary View 2 ยังเป็นการคำนวณด้วยกฎภายใน แสดงคำอธิบายแหล่งผลให้ต่างจาก `result` ในหน้ารายบุคคล ไม่เปลี่ยนสูตรเกณฑ์ View 2 ในงานนี้

## การย้ายขึ้นระบบจริง

1. สำรองชีต EPI, vaccine_rules, Dashboard_Summaries และตรวจปี/identity ซ้ำก่อนย้าย schema
2. Deploy backend ที่ deployment เดิมให้คง `/exec` URL แล้ว deploy frontend รุ่นนี้คู่กัน ไม่ใช้ client เก่าอัปโหลดหลาย chunk กับ receipt รุ่นใหม่
3. ใช้ `setupDatabase()` จาก Apps Script owner หรือ endpoint `setup` ที่ตรวจสิทธิ์ admin/superadmin แล้ว ระบบเพิ่มคอลัมน์ท้ายชีต ไม่เลื่อนข้อมูลเดิม; upsert ก็เพิ่มคอลัมน์ที่ขาดให้ก่อนเขียนได้
4. นำเข้าไฟล์ HDC เดิมใหม่ในโหมดเติมข้อมูลเพื่อเติมคอลัมน์ที่เคยถูกทิ้ง ตรวจจำนวนคนและรหัสศูนย์นำหน้าในทุกอายุ
5. ประมวลผล Dashboard ใหม่ทุกปีที่ใช้งาน (ทั้งปีและไตรมาส); ค่า cache เดิมยังไม่สะท้อนรายการอายุจนกว่าจะประมวลผลใหม่
6. ตรวจเบราว์เซอร์จริงทั้ง desktop/mobile, ทั้งสองมุมมองและไฟล์ export รวม login ของ admin/superadmin/user ต่างหน่วยบริการ

`getEpiData` ต้องมี session; ขอบเขต user อ้างอิงหน่วยบริการจากบัญชี ไม่เชื่อค่าที่ client ขอ `debugBounds`/`debugGetEpiData` ถูกนำออกจาก route ข้อมูลรายบุคคล ไฟล์ HDC ตัวอย่างไม่ได้ commit เข้า Git

## ตรวจสอบในเครื่อง

```sh

npm run lint --prefix frontend
./frontend/node_modules/.bin/vitest run --root frontend
node backend/tests/hdc-import.test.cjs
node backend/tests/vaccine-date-checks.test.cjs
git diff --check
```
