# Features & Core Logic

## 1. Authentication & Authorization (ระบบสมาชิก)
- **Google Login:** เข้าสู่ระบบด้วยอีเมล Google (OAuth2)
- **First-time Setup:** หากล็อกอินครั้งแรก ระบบจะให้เลือก "สถานบริการ (รพ.สต.)" ที่สังกัด 
- **Approval Workflow:** หลังจากเลือกสถานบริการ สถานะผู้ใช้จะเป็น `pending` และต้องรอให้ Super Admin อนุมัติเป็น `approved` จึงจะสามารถเข้าถึงข้อมูลได้
- **Role-based Access Control (RBAC):** 
  - **User:** ดูข้อมูลเฉพาะสถานบริการของตนเอง
  - **Admin / Super Admin / สสอ. (00588):** ดูข้อมูลของทุกสถานบริการได้ทั้งหมด

## 2. Data Upload & Processing (การนำเข้าข้อมูล)
- **Excel / JSON Parsing:** อ่านไฟล์ HDC กลุ่มอายุ 1, 2, 3 และ 5 ปีจากเบราว์เซอร์ ตรวจทุกแถวและรักษาคอลัมน์ว่าง
- **Data Cleaning:** 
  - แปลงค่า `<NA>` เป็น `null`
  - คอลัมน์ที่ชื่อมีคำว่า `hosc` หรือ `hosp` จะถูกบังคับให้อ่านค่าเป็น String เพื่อรักษาเลข `0` นำหน้า
- **Upsert:** ใช้ PID + หน่วยบริการ + ปีงบประมาณ + sex + birth + check_vhid ต้องตรงกันทั้งหมด CID ที่ปิดบังด้วย `*` ซ้ำกันได้จึงไม่ใช้เป็นตัวระบุ ถ้าไม่มี PID ต้องมี CID ไม่ปิดบังแทน โดยยังตรงส่วนประกอบอื่นครบ ไม่ใช้ CID สำรองจับคู่ข้ามคีย์
- **Update:** คอลัมน์ไม่ได้ส่งมารักษาค่าเดิม เซลล์ว่าง/null ที่ส่งมาล้างค่านั้น
- **Data Sync:** ค่าเริ่มต้นเป็นเติมข้อมูล ไม่ deactivate คนที่ไม่อยู่ในไฟล์ โหมดซิงค์ไฟล์เต็มจะ deactivate ได้เมื่อรับครบทุก chunk และเฉพาะปี/หน่วยบริการของ batch ที่ตรวจแล้ว
- **As of Date:** บันทึกเวลาที่ทำการอัปโหลดลงใน `audit_logs` เพื่อให้หน้า Dashboard นำไปแสดงว่า "ข้อมูลอัปเดตล่าสุด ณ วันที่..."

## 3. EPI Tracking Dashboard (ระบบติดตามวัคซีน)
### 3.1 เกณฑ์การประเมินและการติดตามวัคซีน (อ้างอิงมาตรฐาน HDC)
ระบบมี **2 ตัวชี้วัด** ได้แก่ มุมมองที่ 1 (รายชนิดวัคซีน) และมุมมองที่ 2 (Fully Immunized) ซึ่งใช้ข้อมูลรายบุคคลจาก Excel Upload ส่วนแท็บภาพรวม OpenData ดึงข้อมูลรวมจาก HDC OpenData API แยกต่างหาก

มุมมองที่ 2 สำหรับเด็กอายุ 1, 2, 3 และ 5 ปีแสดงรายชื่อและประวัติจาก HDC โดยใช้ค่า `result` ที่นำเข้าโดยตรง ไม่คำนวณผลใหม่ด้วยกฎในแอป รายละเอียดดู [การแสดงข้อมูลรายบุคคลจาก HDC](hdc-record-display.md) ส่วนเกณฑ์ด้านล่างเป็นข้อมูลอ้างอิงของระบบกฎเดิม

> **ข้อกำหนดปัจจุบัน:** รายการแสดงมุมมองที่ 1 แยกอายุและข้อจำกัด mapping ใช้ [HDC column upgrade](hdc-column-upgrade.md) รายละเอียดรายเข็มด้านล่างเป็นข้อมูลอ้างอิงเดิมที่ต้องอ่านร่วมกับข้อจำกัดนี้

**มุมมองที่ 1: การติดตามวัคซีนรายไตรมาส / รายช่วงอายุ (อ้างอิง HDC Report 1)**
ใช้สำหรับแจ้งเตือนเจ้าหน้าที่ (รายบุคคล) ว่าเด็กอายุถึงเกณฑ์แล้วขาดวัคซีนตัวไหนบ้าง (อ้างอิงชื่อคอลัมน์จากฐานข้อมูล):
- **แรกเกิด (0-1 เดือน):** BCG แรกเกิด (`bcg_date`), HBV แรกเกิด (`hbv1_date`)
- **2 เดือน:** DTP 2 เดือน (`dtp1_date`), HBV 2 เดือน (`hbv2_date`), Hib 2 เดือน (`hib1_date`), IPV 2 เดือน (`ipv1_date`), Rota 2 เดือน (`rv21_date` หรือ `rv31_date`), PCV 2 เดือน (`pcv1_date`)
- **4 เดือน:** DTP 4 เดือน (`dtp2_date`), HBV 4 เดือน (`hbv3_date`), Hib 4 เดือน (`hib2_date`), IPV 4 เดือน (`ipv2_date`), Rota เข็ม 2 (`rv22_date` หรือ `rv32_date`), PCV 4 เดือน (`pcv2_date`)
- **6 เดือน:** DTP 6 เดือน (`dtp3_date`), HBV 6 เดือน (`hbv4_date`), Hib 6 เดือน (`hib3_date`), OPV 6 เดือน (`opv1_date`), Rota เข็ม 3 (`rv33_date` - ถ้ามี), PCV 6 เดือน (`pcv3_date`)
- **9 เดือน:** MMR 9 เดือน (`mmr1_date`)
*(หมายเหตุ: Rota ครบถ้วนตามเกณฑ์ จะพิจารณาจากชนิดวัคซีน หากเป็นชนิด 2 ครั้งเช็ค `rv21, rv22` หากเป็นชนิด 3 ครั้งเช็ค `rv31, rv32, rv33`)*
*(หมายเหตุ: หากอายุยังไม่ถึงเกณฑ์ เช่น อายุ 3 เดือน ระบบจะไม่แสดงผลว่าขาดวัคซีนของช่วง 4 เดือน)*

**มุมมองที่ 2: การประเมินเด็กอายุครบ 1 ปี (Fully Immunized) (อ้างอิง HDC Report 2)**
ใช้ประเมินเมื่อเด็กมีอายุครบ 1 ปีบริบูรณ์ ว่าได้รับวัคซีนพื้นฐานครบถ้วนหรือไม่ โดยเด็ก 1 คนจะผ่านเกณฑ์ "Fully Immunized" ก็ต่อเมื่อได้รับวัคซีนครบตามนี้:
- **BCG:** 1 ครั้ง (`bcg_date`)
- **HBV:** 3 ครั้ง (ต้องมีวันที่ใน `hbv1_date` AND `hbv2_date` AND `hbv4_date` — HBV แรกเกิด + 2 เดือน + 6 เดือน ตาม HDC, `hbv3_date` (สำหรับวัคซีนรวม) ไม่นับรวม)
- **DTP:** 3 ครั้ง (เช็ค `dtp1_date` AND `dtp2_date` AND `dtp3_date` ต้องมีค่าครบทั้ง  3)
- **Hib:** 3 ครั้ง (เช็ค `hib1_date` AND `hib2_date` AND `hib3_date` ต้องมีค่าครบทั้ง 3)
- **IPV:** 2 ครั้ง (เช็ค `ipv1_date` AND `ipv2_date`)
- **OPV:** 3 ครั้ง (เช็ค `opv1_date` (2 ด.), `opv2_date` (4 ด.), และ `opv3_date` (6 ด.) ตามลำดับแบบตรงไปตรงมา)
- **MMR:** 1 ครั้ง (`mmr1_date`)
- **Rota:** ครบถ้วนตามเกณฑ์ (มีข้อมูลครบ 2 เข็มใน `rv2` หรือครบ 3 เข็มใน `rv3`)
*(หากได้รับครบตามรายการด้านบน จะถือว่าผ่านเกณฑ์ Fully Immunized และนำไปคิดเป็นร้อยละความครอบคลุมภาพรวมของ รพ.สต.)*

**มุมมองที่ 1: การติดตามวัคซีนรายไตรมาส / รายช่วงอายุ (เด็ก 3 ปี)**
- **2 ปีครึ่ง - 3 ปี:** LAJE 2 ครั้ง (`j11_date` และ `j12_date`) หรือ JE 3 ครั้ง (`je1_date`, `je2_date`, `je3_date`)

**มุมมองที่ 2: การประเมินเด็กอายุครบ 3 ปี (Fully Immunized)**
ใช้ประเมินเมื่อเด็กมีอายุครบ 3 ปีบริบูรณ์ ว่าได้รับวัคซีนพื้นฐานครบถ้วนหรือไม่:
- **BCG:** 1 ครั้ง (`bcg_date`)
- **HBV:** 3 ครั้ง (`hbv1_date`, `hbv2_date`, `hbv4_date`)
- **DTP:** 4 ครั้ง (`dtp1_date` ถึง `dtp4_date`)
- **Hib:** 3 ครั้ง (`hib1_date` ถึง `hib3_date`)
- **IPV:** 2 ครั้ง (`ipv1_date`, `ipv2_date`)
- **OPV:** 2 ครั้ง (`opv3_date` AND `opv4_date` สำหรับ 6 และ 18 เดือน) ตาม report template ข้อ 6; ไม่บังคับ `opv1_date` หรือ `opv2_date` ในมุมมองนี้
- **MMR:** 2 ครั้ง (`mmr1_date`, `mmr2_date`)
- **Rota:** ครบถ้วนตามเกณฑ์ (2 หรือ 3 ครั้ง)
- **LAJE 2 ครั้ง หรือ JE 3 ครั้ง:** (`j11_date` AND `j12_date`) หรือ (`je1_date` AND `je2_date` AND `je3_date`)

ค่าเริ่มต้นใน `seedVaccineRules` ใช้กรอบ report template ข้อ 6 ที่ได้รับสำหรับมุมมองที่ 2 อายุ 3 ปี โดย IPV ต้องมีทั้งสองเข็ม ไม่มีทางเลือกให้ OPV ชดเชย IPV ส่วน HBV คง mapping เดิม (`hbv1_date`, `hbv2_date`, `hbv4_date`) พร้อมหมายเหตุรอยืนยันคอลัมน์เข็ม 6 เดือนจากรายงาน HDC

Template ยังไม่ได้แจกแจงเงื่อนไขวันที่ซ้ำ/ระยะห่างหรือสูตรผสม จึงไม่เพิ่มข้อสันนิษฐานเหล่านี้ใน seed ผลผ่าน/ไม่ผ่านอ้างอิง `result` ของ HDC; การแก้ seed นี้ไม่เปลี่ยนตัวตรวจวันที่ใน engine ปัจจุบัน การทดลองเฉพาะความครบของคอลัมน์กับข้อมูล active 232 แถวให้ผลตรง 231 แถว โดยอีก 1 แถวยังอธิบายสาเหตุไม่ได้แน่ชัด

การแก้ค่าเริ่มต้นไม่อัปเดต `vaccine_rules` ที่มีอยู่โดยอัตโนมัติ และ `seedVaccineRules(..., ..., true)` จะ reset ทุกกลุ่มอายุของปีที่เลือก จึงไม่ใช่คำสั่งอัปเดตเฉพาะกลุ่ม 3 ปี

> **หมายเหตุ:** มุมมองที่ 1 และ 2 ประมวลผลจาก **ข้อมูลรายบุคคล (Excel Upload)** เท่านั้น ไม่เกี่ยวข้องกับมุมมองที่ 3

### 3.2 มุมมองที่ 3: สถิติรวมจาก HDC OpenData API (แยกต่างหาก)
> ข้อมูลประเภทนี้เป็น **ตัวเลขรวม (Aggregate)** เท่านั้น ไม่ใช่ข้อมูลรายบุคคล แสดงในหน้า Dashboard แยกมุมมองต่างหาก

#### 3.2.1 ความครอบคลุมรายช่วงอายุ / รายเดือน (`s_epi1`)
- **API:** `POST https://opendata.moph.go.th/api/epi/report`
- **Payload:** `{"tableName": "s_epi1", "year": "2569", "province": "54", "type": "json"}`
- **Schema Ref:** https://opendata.moph.go.th/api/report_schema/s_epi1

| คอลัมน์ใน API (suffix `_{mm}`) | ความหมาย | ตรงกับ HDC รายการ |
| :--- | :--- | :--- |
| `bcg` | BCG แรกเกิด | BCG แรกเกิด |
| `hbv` | HBV แรกเกิด | HBV แรกเกิด |
| `dtp1` | DTP เข็ม 1 | DTP 2 เดือน |
| `dtp2` | DTP เข็ม 2 | DTP 4 เดือน |
| `dtp_hb3` | DTP เข็ม 3 + HBV | DTP 6 เดือน, HBV 6 เดือน |
| `hbv2` | HBV เข็ม 2 | HBV 2 เดือน |
| `hbv3` | HBV เข็ม 3 (วัคซีนรวม) | HBV 4 เดือน |
| `hbv4` | HBV เข็ม 4 | HBV 6 เดือน |
| `hib1` | Hib เข็ม 1 | Hib 2 เดือน |
| `hib2` | Hib เข็ม 2 | Hib 4 เดือน |
| `hib3` | Hib เข็ม 3 | Hib 6 เดือน |
| `ipv1` | IPV เข็ม 1 | IPV 2 เดือน |
| `ipv` | IPV ครบ 2 เข็ม | IPV 4 เดือน |
| `opv3` | OPV | OPV 6 เดือน |
| `mmr` | MMR | MMR 9 เดือน |
| `rota1` | Rota เข็ม 1 | Rota 2 เดือน |
| `rota` | Rota ครบถ้วน | Rota (ครบถ้วน) |

| `target` | จำนวนเด็กเป้าหมาย | — |

*(suffix `{mm}` คือรหัสเดือน Fiscal Year ไทย: `10`=ตค., `11`=พย., `12`=ธค., `01`=มค., ..., `09`=กย.)*

#### 3.2.2 ความครอบคลุม Fully Immunized (`s_epi_complete`)
- **API:** `POST https://opendata.moph.go.th/api/epi/report`
- **Payload:** `{"tableName": "s_epi_complete", "year": "2569", "province": "54", "type": "json"}`
- **Schema Ref:** https://opendata.moph.go.th/api/report_schema/s_epi_complete

| คอลัมน์ใน API | ความหมาย |
| :--- | :--- |
| `hospcode` | รหัสหน่วยบริการ 5 หลัก (ต้องรักษาเลข 0 นำหน้า) |
| `target` | เด็กเป้าหมายรวมทั้งปี |
| `result` | เด็กที่ผ่านเกณฑ์ Fully Immunized รวมทั้งปี |

> ตาราง `s_epi_complete` **ใช้ร่วมกันสำหรับทุกช่วงอายุ** (1 ปี, 2 ปี, 3 ปี, 5 ปี) รองรับการต่อยอดในอนาคตได้ทันที

### 3.6 การตรวจข้อมูลวันที่จาก Vaccine Rules Engine

ผู้ดูแลแก้แต่ละเกณฑ์ เลือกอนุญาตตรงวันเกิด/เตือนก่อนวันเกิด เพิ่มหรือลบคู่เข็มห้ามวันซ้ำ และคู่ลำดับวันที่ จากนั้นบันทึกฉบับร่างและยืนยันบันทึกตามขั้นตอนเดิม หน้าทบทวนแสดงความเปลี่ยนแปลงด้วยชื่อเข็ม

ทั้งสองมุมมองแสดงรายละเอียดข้อสังเกตเฉพาะในประวัติ ผลรายชนิดที่มีแต่ข้อผิดปกติแสดง “ตรวจสอบประวัติวัคซีน” โดยไม่เรียกข้อผิดปกติว่า “ขาด” ส่วน Fully Immunized คงผล HDC ที่นำเข้า การตั้งค่าวันที่มีขอบเขตตามกฎ ปีงบประมาณ และกลุ่มอายุที่เลือก

Rota ในข้อมูลระบบมีชุดคอลัมน์ 2 เข็ม (`rv21`, `rv22`) และ 3 เข็ม (`rv31`, `rv32`, `rv33`); “Rota เข็ม 1” เป็นเกณฑ์เข็มแรก ส่วน “Rota (ครบถ้วน)” เป็นเกณฑ์ความครบชุด ไม่ใช่ชื่อผลิตภัณฑ์สองชนิด ตัวตรวจค่าเริ่มต้นไม่จับวันซ้ำข้ามสองชุดนี้

### 3.7 การเปรียบเทียบข้ามปีงบประมาณ (Year Comparison)

- สรุปประจำปีของแต่ละกลุ่มอายุอ่านจาก `Dashboard_Summaries` โดย **backend เป็นผู้ตัดสินลำดับความสำคัญของแถว**: ใช้แถว `<ตาราง>_<ปี>_all` ก่อน และใช้แถวรุ่นเดิม `<ตาราง>_<ปี>` เฉพาะเมื่อไม่มีแถว `_all` ของปี/ตารางนั้น — ส่งกลับแถวเดียวต่อ (ตาราง, ปี) เท่านั้น ฝั่งหน้าเว็บไม่เลือกเองด้วยเวลา `updated_at`
- ปีงบประมาณที่เสนอให้เปรียบเทียบมาจาก **ปีที่มีสรุปประจำปีใช้งานได้** (แยก `summaryData` เป็น JSON ได้และมี `total`/`view2Coverage`/`view2Passed` เป็นตัวเลข) ของกลุ่มอายุที่เลือกเท่านั้น ไม่ใช้ปีจากการตั้งค่าทั่วไปหรือปีที่มีเพียงกฎวัคซีน
- ปีที่ไม่มีสรุปแสดงเป็น “ไม่มีข้อมูลสรุป” — **ไม่แปลงเป็น 0% หรือ 0 คน** ส่วนค่า 0 ที่เป็นข้อมูลจริงยังแสดง 0 ตามปกติ
- ตัวเลือกปีงบประมาณมาจากกลุ่มอายุที่เลือกเท่านั้น (ไม่รวมข้ามกลุ่มอายุ) โดย **ค่าเริ่มต้นคือ 2 ปีล่าสุดที่ใช้งานได้** (มีปีเดียวก็ใช้ปีนั้น) เลือกได้**สูงสุด 5 ปี** และผู้ใช้ปลดเลือกทุกปีได้ — หน้าจะแสดงข้อความให้เลือกอย่างน้อย 1 ปี โดย**ไม่เลือกปีให้อัตโนมัติซ้ำ** การเปลี่ยนกลุ่มอายุจะตั้งค่าเริ่มต้นใหม่เป็น 2 ปีล่าสุดของกลุ่มนั้น
- แต่ละปีงบประมาณเป็น **สรุปประจำปีที่จัดเก็บไว้ (snapshot) ณ เวลาที่คำนวณของปีนั้น** เวลา `updated_at` คือเวลาคำนวณ/บันทึกสรุป (แสดงเป็น “ข้อมูลสรุป ณ วันที่ …”) ไม่ใช่เวลาอัปโหลดข้อมูลต้นทาง และแต่ละปีอาจมีเวลาคำนวณต่างกัน — ไม่ใช่การคำนวณใหม่ ณ วันเดียวกัน
- KPI ใช้**ปีล่าสุดที่มีสรุปจริง**จากปีที่เลือก: ความครอบคลุม Fully Immunized, ส่วนต่างจากปีที่เลือกก่อนหน้าที่มีข้อมูล (หน่วย **จุด percentage points (pp)** ไม่ใช่เปอร์เซ็นต์เปลี่ยนแปลง), ส่วนต่างจากเป้าหมาย (pp) และ ผ่านเกณฑ์ / เข้าเกณฑ์ประเมิน
- เป้าหมายรายปีอ่านผ่าน `useTargetSettings` ด้วยไตรมาส `'all'` (แปลงเป็นเป้าหมาย Q4 ของปีนั้น) — ปีที่ไม่ได้กำหนดเป้าหมายแสดง “ไม่ได้กำหนดเป้าหมาย” **ไม่ใช้เป้าหมาย 0 แทน**
- สรุปรุ่นสัญญาปัจจุบัน (มี `view2ApplicableTotal` และ `view2PendingCount` เป็นตัวเลข) แสดงองค์ประกอบ **ผ่านเกณฑ์ / ไม่ผ่านเกณฑ์ / ยังไม่เข้าเกณฑ์ประเมิน** โดย “ไม่ผ่านเกณฑ์” คำนวณ ณ ตอนแสดงผลจาก `view2ApplicableTotal − view2Passed` เท่านั้น (ไม่ได้เก็บในสรุป และไม่ใช้ `total − passed`)
- สรุปรุ่นเดิม (legacy) ยังแสดงความครอบคลุมและจำนวนผ่านเกณฑ์ แต่**รายละเอียดที่ต้องอาศัยตัวส่วน (เข้าเกณฑ์ประเมิน / ไม่ผ่านเกณฑ์ / ยังไม่เข้าเกณฑ์ประเมิน) ไม่สามารถแสดงได้** แสดงเป็น “—” พร้อมข้อความแจ้งว่า “ไม่มีข้อมูลรายละเอียดสำหรับ summary รุ่นนี้” — ไม่เติมค่า 0 หรืออนุมานตัวส่วนแทน
- สถานะต่าง ๆ แยกกันชัดเจน: ข้อผิดพลาด API ปีที่ใช้ได้ / ข้อผิดพลาด API สรุป / ข้อผิดพลาดการตั้งค่าเป้าหมาย (แสดงเป็นข้อผิดพลาด ไม่ใช่ “ไม่มีข้อมูล”) กลุ่มอายุที่ไม่มีปีใช้ได้เลย (สถานะไม่มีข้อมูลระดับหน้า) และการปลดเลือกทุกปี (แจ้งให้เลือกอย่างน้อย 1 ปี)
- **การเปรียบเทียบรายสถานบริการ (รพ.สต.) ข้ามปีงบประมาณ** ใช้ค่าที่จัดเก็บไว้ใน `facilityBreakdownV1` / `facilityBreakdownV2` ของสรุปประจำปีของปีที่เลือกและกลุ่มอายุที่ใช้งานเท่านั้น (ไม่ดึงข้อมูลรายบุคคลหรือคำนวณใหม่) โดย **`hoscode` เป็นตัวระบุสถานบริการแบบสตริงตามที่จัดเก็บ** — ใช้เป็นคีย์เชื่อมข้ามปีและแสดงผลตรงตามตัวอักษร รักษาเลขศูนย์นำหน้าเสมอ (เช่น `06413` และ `6413` เป็นคนละสถานบริการ) ชื่อสถานบริการใช้เพื่อแสดงผลเท่านั้น (ใช้ชื่อล่าสุดของปีที่เลือกที่มีชื่อ) ไม่ใช้เชื่อมข้อมูล
  - แสดงค่าความครอบคลุม View 1 และ View 2 ต่อสถานบริการต่อปีตามที่จัดเก็บ — ปีใดหรือมุมมองใดที่ไม่มีข้อมูลของสถานบริการนั้นแสดง `—` **ไม่แปลงเป็น 0** ส่วนค่า 0 ที่เป็นข้อมูลจริงยังแสดง 0 ตามปกติ
  - ส่วนต่างข้ามปีของสถานบริการคำนวณจากความครอบคลุม View 2 ของปีที่เลือกที่มีข้อมูลเท่านั้น (หน่วย pp) และส่วนต่างจากเป้าหมายใช้เป้าหมาย View 2 รายปีตามข้อตกลงเดียวกับระดับปี (`'all'` → Q4) — ปีที่ไม่ได้กำหนดเป้าหมายแสดง “ไม่ได้กำหนดเป้าหมาย” ตามปกติ
  - ค่ารายสถานบริการของแต่ละปีเป็นข้อมูลสรุปสแนปชอตของปีนั้น (แสดงเวลา `ข้อมูลสรุป ณ วันที่ …` ประจำปีเหมือนระดับปี)
